# Solar Trade Hub dashboard update 2.4

This dashboard is aligned to the backend supplied as backend(2).rar and the Master Architecture v1.1. It is a frontend integration update; the backend source and database have not been changed or deployed.

## Connected in this update

| Area | Working frontend integration |
| --- | --- |
| Payments | Management listing, server filters and pagination, full detail, processing, verified-paid confirmation, failure and fulfilment retry |
| Supplier products | Catalogue mapping decision, publication readiness, per-product FREE ENABLE grant/revoke and optional publish attempt |
| External catalogue offers | Per-supplier FREE ENABLE grant/revoke from the product details page |
| Orders | Server-backed fulfilment transitions and optional audit note; paid cancellation remains blocked until refund |
| Operations dashboard | Approval, mapping, stock, payment and subscription queues; listing health; revenue separated by purpose and currency |
| Role editor | Fetches the backend permission catalogue; preserves compatible existing dashboard keys |
| Range Tokens | Read access aligned to backend permissions; balance adjustment controls require range_tokens.manage |
| Local reference data | Local Categories and Local Brands screens restored to navigation for products.manage; these do not edit the external master catalogue |
| Home activity | Replaced the disconnected zero-only order series with the server's current-year monthly order report; missing coverage remains unavailable |
| Navigation | Payment, subscription, plan and bid menu/route permissions aligned to the actual backend |

Existing supplier applications, supplier verification, subscriptions/plans, bids, customer requests/offers, installers/applications, tenders, deals, careers/applications, users, content, settings, notifications, support and reporting service connections remain present. The endpoint checker compares directly discoverable Axios calls to the supplied Express routes; it is not an end-to-end assertion for every screen.

## Interface and loading changes

- Payment workspace redesigned with desktop tables and mobile cards, real error/empty/loading states and clear receipt verification controls.
- Product review shows the backend's publication checks, including paid access or a valid free override.
- Operational queues link to the appropriate staff workspace when the account has access.
- Route-level lazy loading replaces the single application bundle; charts are loaded separately.
- Keyboard focus styling, modal focus containment/restoration and reduced-motion behavior improved.
- Removed synthetic metric mini-bars; unavailable comparisons do not imply an upward trend.
- Fixed invalid dark-mode pseudo-element CSS generated by the existing scrollbar styles.

## Validation and limits

- Production TypeScript/Vite build completed successfully.
- Static API path/method checker compared 201 directly discoverable dashboard Axios calls against 331 mounted backend routes, with zero unmatched paths/methods. Dynamic URL variables still require manual/runtime checking.
- Nine browser integration checks passed with zero browser runtime errors. They use fixture API responses, not the live database, and exercise the new payment/product/order flows, role permissions, operational queues and mobile viewport.
- Targeted ESLint checks on the new integration code passed. Repository-wide ESLint still reports existing errors in legacy source (including explicit any, unused legacy arguments and control-character regex rules). No project-wide lint PASS is claimed.
- Vite still reports a size advisory for the separately loaded chart vendor chunk. A passing build is not proof of a three-second live page load.
- No production login, MongoDB writes, real payment receipt, gateway callback or deployed API end-to-end test was performed.

## Backend boundaries that remain

The supplied backend does not yet provide a complete booth booking workflow, tender bid submission/evaluation, installer jobs/leads, signed payment-provider callbacks/refunds, private stock-evidence storage, or checkout for supplier-owned products. Storefront search is not a unified external/supplier catalogue. These are backend/product work, not completed by adding dashboard buttons.

Supplier analytics endpoints in this backend are supplier-owned self-service routes. This administration dashboard does not send dashboard tokens to those routes or embed the trusted analytics-ingestion secret. Cart/wishlist/customer checkout and supplier draft/image operations likewise remain in their appropriate storefront/supplier roles.

The historical secret-exposure finding in the backend's own audit document has not been independently resolved or verified by this frontend update.
